# ООО «СК Держава» — система учёта ремонта оборудования

Учебное веб-приложение для регистрации промышленного оборудования, приёма заявок и контроля этапов ремонта. Интерфейс адаптирован для компьютеров и телефонов.

## Роли

| Роль | Логины | Возможности |
|---|---|---|
| Администратор | admin | Общая панель, все заявки, назначение инженеров, изменение статусов |
| Инженер | engineer1, engineer2 | Просмотр назначенных заявок, работа с этапами ремонта |
| Клиент | client1, client2, client3 | Собственное оборудование, гарантия, создание заявок и просмотр статусов |

## Демонстрационные учётные записи

Для локальной учебной базы запусти setup_demo_users.py. Скрипт создаёт Werkzeug-хеши и обновляет только поле password_hash существующих пользователей.

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | Администратор |
| engineer1 | engineer123 | Инженер |
| engineer2 | engineer123 | Инженер |
| client1 | client123 | Клиент |
| client2 | client123 | Клиент |
| client3 | client123 | Клиент |

Это простые демонстрационные пароли только для локальной учебной базы. Не используй их на реальном сервере и не публикуй приложение в интернете с этими учётными данными.

## Что реализовано

- Авторизация и выход из системы.
- Разграничение доступа по трём ролям.
- Отдельные панели администратора, инженера и клиента.
- Сводные показатели и общий список заявок для администратора.
- Просмотр инженером назначенных ему заявок.
- Кабинет клиента с оборудованием и сроками гарантии.
- Создание заявки только на оборудование текущего клиента.
- Назначение активного инженера на заявку.
- Изменение статусов и запись истории изменений.
- Создание записи ремонта при переходе к диагностике или ремонту.
- Проверка доступности приложения и БД по адресу /health.
- CSRF-защита форм, сессии и хеширование паролей.
- Адаптивное оформление.

## Важно: существующая база данных

Приложение рассчитано на уже созданную базу PostgreSQL derzhava и таблицы roles, clients, employees, users, equipment, repair_requests, repairs, spare_parts, repair_parts, request_status_history.

Приложение не создаёт, не удаляет и не пересоздаёт таблицы. Перед запуском убедись, что база и тестовые записи уже существуют. Скрипт setup_demo_users.py изменяет только password_hash в таблице users.

## Установка на Windows

Открой папку проекта в PowerShell или терминале Visual Studio.

1. Создай виртуальное окружение:

```powershell
py -m venv .venv
```

2. Установи зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

3. Создай файл .env на основе .env.example. Укажи пароль своего локального пользователя PostgreSQL и задай длинный случайный FLASK_SECRET_KEY.

4. Установи демонстрационные пароли:

```powershell
.\.venv\Scripts\python.exe setup_demo_users.py
```

5. Запусти приложение:

```powershell
.\.venv\Scripts\python.exe app.py
```

6. Открой в браузере http://127.0.0.1:5000/login

## Настройки .env

```dotenv
FLASK_SECRET_KEY=replace-with-a-long-random-secret
FLASK_DEBUG=0
FLASK_HOST=127.0.0.1
FLASK_PORT=5000
COOKIE_SECURE=0

DB_HOST=localhost
DB_PORT=5432
DB_NAME=derzhava
DB_USER=postgres
DB_PASSWORD=your_local_postgres_password
```

Не загружай настоящий файл .env в GitHub. Он добавлен в .gitignore.

## Если появляется ошибка

1. Проверь, что служба PostgreSQL запущена.
2. Проверь параметры подключения в .env.
3. Открой http://127.0.0.1:5000/health. При нормальном подключении появится JSON со статусом ok и database connected.
4. Если приложение выдаёт ошибку, смотри подробности в терминале, из которого запущен app.py.

## Локальная диагностика

Для локальной диагностики можно временно установить FLASK_DEBUG=1 в .env. Не включай режим отладки на публичном сервере. После диагностики верни FLASK_DEBUG=0.
