# Система учёта ремонта промышленного оборудования — ООО «СК Держава»

Учебное веб-приложение на Flask и PostgreSQL для учёта оборудования, заявок и этапов ремонта.

## Реализовано
- Авторизация по логину и паролю с проверкой хеша Werkzeug.
- Разделение доступа по ролям: `admin`, `engineer`, `client`.
- Панель администратора со сводными показателями и общим списком заявок.
- Панель инженера с заявками, назначенными на его `employee_id`.
- Кабинет клиента с его оборудованием, заявками и отображением срока гарантии.
- Создание заявки только на оборудование, принадлежащее клиенту.
- Изменение статуса заявки и запись истории статусов.
- Создание/обновление записи ремонта при переходе к диагностике, ремонту или завершению.
- CSRF-защита форм.

## Важно перед первым запуском
Схема PostgreSQL и тестовые записи в базе `derzhava` уже созданы отдельно. Приложение **не создаёт и не изменяет структуру таблиц**.

Значения-плейсхолдеры в `users.password_hash` не являются рабочими паролями. Для каждого тестового пользователя установите пароль локально командой `python set_password.py`. Пароли вводятся скрыто и не сохраняются в репозитории.

## Установка (Windows)
1. Установите Python 3.11+ и PostgreSQL.
2. Склонируйте репозиторий и откройте папку проекта в терминале.
3. Создайте виртуальное окружение: `python -m venv .venv`.
4. Активируйте его в PowerShell: `.venv\\Scripts\\Activate.ps1`.
5. Установите зависимости: `pip install -r requirements.txt`.
6. Скопируйте `.env.example` в `.env`, укажите локальные параметры подключения к PostgreSQL и задайте длинный случайный `FLASK_SECRET_KEY`.
7. Для каждого пользователя из таблицы `users` выполните `python set_password.py` и задайте пароль. Не отправляйте пароли в чат и не добавляйте их в Git.
8. Запустите приложение: `python app.py`.
9. Откройте `http://127.0.0.1:5000`.

## Ожидаемые поля БД
Используются таблицы `roles`, `users`, `clients`, `employees`, `equipment`, `repair_requests`, `repairs`, `request_status_history`. В частности: `roles.role_name`; `users.username/password_hash/role_id/client_id/employee_id/is_active`; `equipment.warranty_until` (генерируемое поле); `repair_requests.request_status/assigned_employee_id`.

## Ограничения текущей версии
- Назначение инженера и управление справочниками пока выполняются администратором напрямую в БД; отдельная административная форма управления пользователями ещё не добавлена.
- Заполнение диагностического заключения, стоимости, использованных запчастей и печатных документов можно развить следующим этапом.
- Перед публикацией в интернете нужно включить HTTPS, установить `COOKIE_SECURE=1`, сменить секретный ключ и настроить резервное копирование БД.
